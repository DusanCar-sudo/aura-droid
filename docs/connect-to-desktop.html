Connect Aura Droid to your desktop

Pairing over USB or Wi-Fi · takes about two minutes

Aura runs on your computer, where your project lives. This app is its remote control. Pairing happens once: the phone trades a short code for its own key, and reconnects on its own from then on.

Before you start — Aura Code installed and working on the desktop, and both devices to hand. You never type a long key: the code you enter is six characters, and the phone swaps it for the real one.

Over USB most reliable

Traffic runs down the cable and never touches the network — nothing to misconfigure, and it works on a café Wi-Fi that blocks devices from seeing each other.

  1. On the desktop Start the server: 
    aura serve
  2. On the desktop Plug the phone in with a USB cable, enable USB debugging on it, then forward the port back to the phone: 
    adb reverse tcp:7337 tcp:7337
  3. On the desktop Ask for a pairing code — it prints six characters: 
    aura devices add "my phone"
  4. On the phone Open Aura, choose With my desktop, and fill in:
    Address127.0.0.1
    Port7337
    Pairing codethe six characters
    Tap Connect.

Over Wi-Fi no cable

Both devices must be on the same network. The connection is encrypted and the desktop's certificate is pinned during pairing, so only that computer can answer afterwards.

  1. On the desktop Start the server on the network. It prints the address to use and an Identity — note the identity down. 
    aura serve --lan
  2. On the desktop Ask for a pairing code: 
    aura devices add "my phone"
  3. On the phone Open Aura, choose With my desktop, and fill in:
    Addressthe IP it printed
    Port7337
    Pairing codethe six characters
    Tap Connect.
  4. On the phone Open Settings and check that Identity matches what the desktop printed. They should be the same eight characters.
About the code — it is six characters, lasts about ten minutes, and works once. If it is refused, it has almost certainly expired or already been used: run aura devices add again for a fresh one.
If Identity ever changes and you did not re-pair, stop and find out why. Over Wi-Fi that means something other than your desktop is answering on that address. Over USB there is no identity to check, because the traffic never leaves the phone.

If it will not connect

What you seeWhat to do
“That code was not accepted” Get a fresh code — they expire in about ten minutes and work once. Over USB, check adb reverse is still set: it is lost every time the cable is unplugged.
“Could not reach …” The desktop is not answering. Check aura serve is still running, and over Wi-Fi that you used --lan, the address is right, and both devices are on the same network.
Connects, then drops Normal when the phone sleeps or changes network. It reconnects by itself; the header shows a countdown while it does.
Wi-Fi refuses but USB works Many home and public networks block devices from reaching each other. Use the cable, or a network you control.
No desktop at all Choose On this phone only on the start screen and use your own API key. You can pair a desktop later without losing anything.
